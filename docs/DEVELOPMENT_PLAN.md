# 分阶段开发计划

各阶段以可运行的实际产出验收，不以页面数量、连续学习天数或占位内容计进度。当前执行状态见 PROGRESS，以下未标明完成的项目均是计划。

## A：可用 MVP（本轮）

1. 检查仓库，保留已有工作，建立独立项目目录和依赖锁文件。
2. 确立课程内容、进度数据、DAG、实验数学与页面结构的边界。
3. 编写函数、线性函数、Python 函数、向量、点积五章完整课程。
4. 实现路线、章节导航、四层解释、真实 SVG 实验、自测和参考代码。
5. 实现 IndexedDB 持久化、深浅主题、草稿、代码与实验参数保存。
6. 实现思路 checkpoint、恢复、复习标记和全量数据导入导出。
7. 以 Web Worker + 自托管 Pyodide 运行本组纯 Python 实验，显示真实错误及断言结果。
8. 执行构建、单元测试、Python 参考验证和实际浏览器检查，修复问题。
9. 补齐 README、架构、完整课程图、进度与测试报告，提供本地启动和静态部署方式。

A 验收：首五章能使用；图形操作有效；刷新不丢状态；保存思路后可恢复；核心功能不要求账号或模型 API；桌面和手机能完成主要流程；测试结果明确。

## B：完整学习工具

优先级按恢复能力、实验可靠性和教学反馈排序：

- 强化代码实验：每次运行隔离、停止与超时、输出上限、版本化实验、错误定位、更好的编辑体验。
- 增加内容自动化验收：所有参考实现与测试批量执行；公式渲染检查；链接检查；DAG 与可用教材一致性。
- 扩展恢复：当前阅读锚点、实验历史、待理解问题列表、可编辑恢复摘要；数据 schema 迁移。
- 依赖图支持缩放、聚焦先修链和复习视图；保持键盘与屏幕阅读器替代路径。
- 可选 AI 导师后端：OpenAI 兼容提供商，服务端密钥，提示优先，用户主动要求完整解答。
- 导出格式稳定性、备份提醒由用户自选；不加入制造焦虑的推送。

B 验收：无 AI 配置仍可学习；提供商失败有真实错误反馈；无密钥泄漏；代码不会在网页服务进程执行；数据迁移与恢复覆盖自动化。

## C：逐阶段发布完整课程

按 knowledge-graph.json 拓扑顺序逐组实施，不一次创建大量空章节。

| 发布组 | 实际作品 | 核心验证 |
| --- | --- | --- |
| 数学补全 | 幂/对数、矩阵、概率、导数、梯度和最优化实验 | 边界值、图像与数值一致、有限差分检查 |
| 机器学习 | 无框架回归、分类、训练和验证 | 数据划分正确、梯度数值对照、损失趋势与泛化分析 |
| 神经网络 | 微型 autodiff、MLP、优化器与 PyTorch 对照 | 梯度检查、图拓扑、累积梯度、训练可复现 |
| Transformer | 注意力、位置、残差、归一化、mask 与数据流 | 每步形状、softmax 行和、mask 不泄露未来 |
| GPT | 小数据训练、保存、加载、采样和评估 | 训练/验证边界、重载一致、生成限制和种子 |
| 现代 LLM | KV Cache、量化、LoRA、对齐和论文实验 | 缓存正确性、误差、资源指标、评估污染讨论 |

每组发布流程：教材审查 → 可操作实验 → 参考代码与检测 → 数学/代码对照 → 自动化与移动检查 → 修复 → 阶段验收报告 → 标记对应图节点 available。数学和技术解释应明确教学简化及适用条件。

## D：深入 GPT 实现

交付独立本地 Python 工程，与课程逐章对应。包括原始文本和许可说明、数据处理、字符/子词 tokenizer、embedding、causal attention、Transformer block、输出头、cross-entropy、训练、checkpoint 和生成 CLI。

每个关键运算可打印输入输出形状并在网站中对照；训练规模以普通开发者设备可复现为准，不承诺商用效果。对比 temperature、top-k、top-p 的生成，记录可复现评估；增量加入 KV Cache、量化与 LoRA，比较正确性和资源变化。

D 验收是学习者能够说明自己模型的每个核心计算步骤，以及一个实验结果支持什么、不支持什么。

## 后续 Agent 接手顺序

1. 阅读 README、PROGRESS、TEST_REPORT，确认真实运行状态和已知问题。
2. 阅读 ARCHITECTURE、types.ts、课程数据和完整 DAG，不更改稳定 ID。
3. 执行现有检查，再选择一个有完整先修的课程组实现。
4. 内容、实验、检测和文档一起提交；更新实际状态，不把计划写成已完成。
