# 开发与维护计划

本轮目标已从首五章 MVP 扩展为六阶段 83 章教材、六类专项实时实验、三个独立 Python 工程以及可选 AI 导师。本文区分现有交付结构和后续工作；最终运行结果与限制以 `PROGRESS.md`、`TEST_REPORT.md` 为准，不用页面数量或模型自述代替验证。

## 当前交付范围

| 阶段 | 章节数 | 可检查产物 |
| --- | --- | --- |
| 数学基础 | 23 | 函数、向量、矩阵、概率、微积分与最优化，数值/SVG 对照与标准库练习 |
| 机器学习 | 9 | 数据与参数、回归、损失、训练、泛化、分类与逻辑回归；独立回归工程 |
| 神经网络 | 11 | 神经元、MLP、批次、计算图、反传、手写自动微分、优化器、正则与框架对照 |
| Transformer | 16 | 文本表示、Token、Embedding、序列模型、注意力、QKV、多头、位置、残差、归一化与因果结构 |
| GPT | 13 | 语料到分词、模型、损失、训练、断点、采样与评估；本地真实 PyTorch tiny GPT |
| 现代 LLM | 11 | 预训练、SFT、偏好优化、推理、缓存、量化、LoRA、资源、幻觉、评估与论文阅读 |

每章遵守统一 `Lesson` 契约，提供两节以上直觉、数学和深入解释，附实验、起始代码、完整参考、真实断言、自测与来源。基础 `MathLab` 加六个专项实验覆盖不同知识点；图像与表格响应实际计算，简化模型需说明其适用范围。

`projects/regression/` 与 `projects/micrograd/` 可仅用标准库运行；后者含真实标量反向自动微分和可复现 XOR MLP。`projects/tiny-gpt/` 在本地安装 PyTorch 后实际训练 decoder-only Transformer、验证因果性、保存/加载与继续训练、逐字符采样；语料来源与许可随项目提供。构建将三个工程打包为 `/downloads/` ZIP。网页的缩小概率实验与本地张量模型分别验收，不声称浏览器能运行完整 torch。

## 导师交付与边界

导师通过同源 Node 或 Worker 代理连接 OpenAI 兼容 Chat Completions。服务端管理提供商、模型与密钥，前端只展示状态、提问、难度与模式。默认提示优先；学习者主动选择完整解答后，服务端才加入参考代码和验收测试。当前章教材由服务端查找，客户端不能替换规范教材。

代码/最近错误、笔记分别由默认关闭的复选框决定是否分享，服务端再次检查分享标记。章节对话与未发送问题保存在本地，支持取消、重试与真实连接错误反馈；Markdown 和 KaTeX 呈现不解析原始 HTML。提示策略不是保证模型绝不泄露答案的安全证明，回复仍需用教材和程序核查。

服务端具备输入校验、请求/响应上限、60 秒取消、同源检查、服务端上游地址约束和每进程/isolate 的尽力限流。公开部署的身份认证、分布式额度、可信客户端地址与费用控制仍应由部署网关承担。Worker 不是 Python 恶意代码沙箱；网页 Worker 也只为本机学习者主动运行代码提供独立响应环境。

## 本轮集成验收顺序

1. 核对 83 个稳定 ID、六阶段顺序、先修 DAG、教材标题与实际可用性一致，原五章笔记仍可读取。
2. 对每章执行内容门槛、公式严格渲染、参考程序断言与 TODO 起始代码检查；错误用真实失败信息定位，不放宽门槛掩盖缺内容。
3. 核对六个专项实验的公式、边界、形状与数值，验证滑块或按钮确实改变图、表和结果；复用节点、因果 mask、概率归一化等使用独立性质测试。
4. 在真实 CPython 中测试回归与 micrograd。为 tiny GPT 安装独立本地 PyTorch 环境，验证训练下降、未来信息不泄漏、重载一致和优化器恢复；记录环境与种子。
5. 构建并实际解压三个下载 ZIP，确认源码、依赖、许可与运行命令完整，排除虚拟环境、缓存、凭证和训练检查点。
6. 测试主题、草稿、实验参数、对话与 checkpoint 的刷新恢复和 JSON 往返。新增 lab 参数必须同步存储白名单与范围，避免可交互却无法恢复。
7. 测试导师未配置、错误凭证、限流、超时、取消、访问码、分享控制与模式上下文；另行记录真实提供商调用。模拟响应只能证明协议和界面，不证明外部模型质量或服务可用性。
8. 在桌面和手机视口完成路由、导航、图形、代码、导师、恢复与下载检查。核对核心静态站、Node 本地服务、Worker 资源绑定三种边界及部署后的路径。
9. 更新 README、架构、进度与测试报告，明确实际结果、环境依赖与剩余限制；完成后再发布，不把未执行检查描述为通过。

## 后续优先事项

| 优先工作 | 具体范围 | 完成判据 |
| --- | --- | --- |
| 长期恢复 | schema 迁移、阅读锚点、可编辑问题清单与选择性备份 | 旧数据可迁移，损坏导入不覆盖当前记录，恢复行为有端到端测试 |
| 公网导师运维 | 网关身份、持久限流、可信代理头、配额、最小日志与凭证轮换 | 多实例限制一致，未授权不能消耗模型额度，服务错误不暴露凭证 |
| 教材持续审校 | 数学/代码独立复核、链接可达性与来源版本、误区反馈 | 每处修改附可复现校验，保留原 ID 与原笔记，避免无依据结论 |
| 实验可用性 | 键盘与屏幕阅读器、图形替代、减少动态效果、窄屏可读性 | 能不用鼠标完成关键流程，表格和数值说明能独立表达图中信息 |
| 本地 GPT 扩展 | 文档边界处理、更大公开许可语料、受控消融与训练资源记录 | 不泄漏验证集；报告模型、数据、tokenizer、预算、指标与失败样例 |
| 推理实验 | 独立实现并校验 KV cache、低精度或低秩实际工程 | 与无缓存/高精度/完整更新建立正确性对照，再报告速度与内存 |

不把云同步、账号体系、分布式限额、远程代码执行、生产级 KV cache 或完整 RLHF 训练流程列为已交付。若新增远程 Python 执行，必须独立设计容器/微虚拟机、无宿主挂载、网络/资源限制和任务队列；现有导师 API 不承担这项能力。
